# 第 2 章 · 运算符与表达式

> **卷一 · 语言**　|　前置知识：第 1 章　|　建议用时：40 分钟

> 表达式不是“算一下”，而是“按一套规则把值和副作用组合起来”。

第 1 章讲了对象和类型。这一章把对象放进表达式里，观察它们如何被组合、转换、求值。C 的运算符不多，但每一个都带着类型规则和求值顺序规则；真正的难点不是记住优先级表，而是知道**哪一些表达式根本没有唯一答案**。

## 2.1 本章语法地图

| 语法 | 本章出现的位置 |
|------|----------------|
| 算术运算符 | `+ - * / %` |
| 关系与相等运算符 | `< <= > >= == !=` |
| 逻辑运算符 | `&& || !` |
| 位运算符 | `& | ^ ~ << >>` |
| 赋值运算符 | `= += -= *= /= %=` |
| 自增自减 | `++i`、`i++`、`--i`、`i--` |
| 条件运算符 | `cond ? a : b` |
| 逗号运算符 | `(a, b)` |
| 强制类型转换 | `(double)7 / 2` |
| `sizeof` | `sizeof(counter++)` |
| 优先级与结合性 | `2 + 3 * 4` |

## 2.2 表达式、语句与副作用

**表达式**（expression）是能求出一个值的构造。每个表达式都有一个类型；有些表达式还会修改对象，这叫**副作用**（side effect）。

```c
x + 1        // 表达式：求出值，通常没有副作用
x = 1        // 表达式：求出赋值后的值，同时修改 x
x++          // 表达式：求出旧值，同时修改 x
printf("hi") // 表达式：调用函数，可能有副作用
```

在表达式后面加分号，就得到一条**表达式语句**：

```c
x + 1;       // 合法，但结果被丢弃
x = 1;       // 赋值语句
```

C 不要求表达式语句一定“有用”。编译器可能用 `-Wunused-value` 提醒你，但语法上它是合法的。

这一章的主线是：**先看类型，再看结合方式，最后看求值顺序。** 很多“运算符题”只考第一层，真正会咬人的是第三层。

## 2.3 算术运算符

```c
int a = 7, b = 3;

a + b    // 10
a - b    // 4
a * b    // 21
a / b    // 2，整数除法向零截断
a % b    // 1，余数
```

整数除法和取余有几个必须记住的规则：

- 从 C99 开始，除法向零截断，不是向负无穷取整。
- 余数的符号与被除数相同。
- 除数为 0 是未定义行为；`INT_MIN / -1` 在常见平台上也会溢出，同样是未定义行为。
- `%` 只能用于整数类型，不能用于 `float` 或 `double`。

```c
-7 / 3    // -2
-7 % 3    // -1
```

如果想让除法得到浮点结果，至少有一个操作数要是浮点类型：

```c
7 / 2        // 3
(double)7 / 2  // 3.5
7 / 2.0      // 3.5
```

`(double)7 / 2` 中，强制转换只作用于 `7`，然后 `double / int` 触发通常算术转换，`2` 也变成 `double`。

## 2.4 关系、相等与逻辑

关系运算符和相等运算符的结果类型都是 `int`，值为 0 或 1：

```c
3 < 5      // 1
3 == 5     // 0
3 != 5     // 1
```

C 没有专门的布尔类型作为比较结果；`_Bool` 是另一种类型，比较表达式的结果仍然是 `int`。

### 逻辑运算符

`&&`、`||`、`!` 把操作数当作“真/假”：

- 0 为假，非 0 为真。
- `!x` 在 `x == 0` 时得 1，否则得 0。
- `x && y` 在两者都非 0 时得 1，否则得 0。
- `x || y` 在至少一个非 0 时得 1，否则得 0。

逻辑运算符的结果一定是 `int` 的 0 或 1，不会是操作数本身。

### 短路求值

`&&` 和 `||` 保证从左到右求值，并且可能跳过右边：

- `0 && expr`：左边为假，右边**不执行**。
- `1 || expr`：左边为真，右边**不执行**。
- `1 && expr`：右边必须执行。
- `0 || expr`：右边必须执行。

这不是优化，而是语言保证。它让我们可以写：

```c
if (p != NULL && *p == 42) {
    // 只有 p 非空时才解引用
}
```

如果 `&&` 不短路，这个惯用法就会在 `p == NULL` 时崩溃。

[`expressions.c`](expressions.c) 里的 `trace` 函数会打印自己被调用的信息，用来观察短路：

```c
printf("0 && trace(...) = %d\n",
       trace("left 0", 0) && trace("right 1", 1));
```

输出中只有 `left 0`，没有 `right 1`。

### 逻辑与位运算不是一回事

```c
2 && 4    // 1：两者都非零
2 & 4     // 0：按位与，二进制 010 & 100 = 000
2 || 4    // 1：至少一个非零
2 | 4     // 6：按位或，010 | 100 = 110
```

`&&` 和 `||` 关心“是不是零”，`&` 和 `|` 关心“每一位是什么”。在条件里误把 `&` 写成 `&&`，或者反过来，都是常见 bug。

## 2.5 位运算

位运算符直接操作整数的二进制表示：

| 运算符 | 名称 | 例子（8 位示意） |
|--------|------|------------------|
| `&` | 按位与 | `0xB4 & 0x0F = 0x04` |
| `\|` | 按位或 | `0xB4 \| 0x0F = 0xBF` |
| `^` | 按位异或 | `0xB4 ^ 0xFF = 0x4B` |
| `~` | 按位取反 | `~0xB4 = 0x4B`（8 位） |
| `<<` | 左移 | `0xB4 << 2 = 0x2D0` |
| `>>` | 右移 | `0xB4 >> 1 = 0x5A` |

### 无符号与有符号的差别

位运算最适合**无符号整数**：

```c
unsigned int x = 0xB4u;
x & 0x0Fu;    // 低 4 位
x | 0x0Fu;    // 置低 4 位
x ^ 0xFFu;    // 翻转低 8 位
~x;           // 所有位取反
```

对无符号类型：

- 左移相当于乘 2 的幂，结果按 2^N 取模。
- 右移是逻辑右移，高位补 0。
- `~0u` 得到该类型全 1，也就是 `UINT_MAX`。

对有符号类型：

- 左移负数，或者左移后结果不能表示，是未定义行为。
- 右移负数是实现定义的（可能是算术右移，也可能不是）。
- 位运算依赖整数的表示法；C17 并不要求所有平台都用二进制补码。

所以处理位模式时，优先用 `unsigned int`、`uint32_t` 这类无符号类型。

### 移位的边界

移位次数必须是**非负且小于操作数类型的位宽**。下面这些都是未定义行为：

```c
int x = 1;
x << 32;      // 如果 int 是 32 位，移位数等于宽度，UB
x << -1;      // 负数移位，UB
1 << 31;      // 有符号左移溢出，UB（常见 32 位 int）
1u << 31;     // 无符号左移，定义良好（前提是 unsigned int 至少 32 位）
```

最后一行不是“永远安全”，而是“在 `unsigned int` 能表示 2^31 的平台上安全”。C 只保证 `unsigned int` 至少 16 位。

### 一个常用技巧

```c
x & (x - 1)
```

对无符号非零 `x`，这个表达式会清除最低位的 1。例如 `0xB4 & 0xB3 = 0xB0`。它常被用来判断一个数是不是 2 的幂：

```c
if (x != 0 && (x & (x - 1)) == 0) {
    // x 是 2 的幂
}
```

注意 `x - 1` 在 `x == 0` 时会回绕成该类型的最大值；对无符号类型这是定义良好的，但逻辑上要先把 0 排除。

## 2.6 自增、自减与赋值

### 前缀与后缀

```c
int i = 0;

int a = ++i;   // 先加 1，再取新值：a = 1, i = 1
int b = i++;   // 先取旧值，再加 1：b = 1, i = 2
```

- `++i` / `--i`：先修改，表达式的值是修改后的值。
- `i++` / `i--`：表达式的值是修改前的值，修改发生在取旧值之后。
- 两者都会修改 `i`；区别只在表达式的结果。
- 自增自减只能作用于可修改的左值，不能作用于常量或表达式结果。

对整数来说，`++i` 和 `i++` 在 `for` 循环的迭代部分通常没有性能差别。不要为了“更快”写难以阅读的代码。

### 复合赋值

```c
x += 5;    // 等价于 x = x + 5
x -= 3;
x *= 2;
x /= 4;
x %= 4;
```

复合赋值的左操作数只求值一次。对于简单变量这看不出来，但对于 `a[i++] += 1` 这种表达式，差别就很重要；不过这种写法本身也容易制造求值顺序问题，不建议。

### 赋值是右结合的

```c
a = b = c = 0;   // 等价于 a = (b = (c = 0))
```

赋值表达式本身有一个值，就是赋值后左操作数的值。C 里赋值表达式不是左值（这一点和 C++ 不同），所以不能写 `(a = b) = c`。

### `=` 与 `==`

```c
if (x = 3) { ... }    // 赋值，条件恒为真
if (x == 3) { ... }   // 比较
```

编译器通常会用 `-Wparentheses` 提醒“建议在赋值外面加括号”。把常量写在左边（`if (3 == x)`）是一种老式防御写法，但现代编译器已经能很好地发现这类错误。

## 2.7 条件运算符与逗号运算符

### `?:`

```c
int max = (a > b) ? a : b;
const char *parity = (n % 2 == 0) ? "even" : "odd";
```

条件运算符只求值一个分支：条件为真求第二个操作数，否则求第三个。它是 C 里唯一的三元运算符，结合性是右结合：

```c
a ? b : c ? d : e    // 等价于 a ? b : (c ? d : e)
```

两个分支的类型会经过转换，得到一个共同类型。例如：

```c
double x = flag ? 1 : 2.0;   // 1 被转换成 double
```

在 C 里，条件表达式不是左值，不能写 `(flag ? a : b) = 1`。

### 逗号运算符

逗号在 C 里有两个身份：

1. 分隔函数参数、声明符等，不是运算符。
2. 在表达式中作为运算符：先求左边，丢弃结果，再求右边，整个表达式的值是右边。

```c
int x = (1, 2, 3);   // x = 3
```

逗号运算符的优先级最低，所以括号很重要：

```c
f(a, b)      // 两个参数
f((a, b))    // 一个参数，值是 b
```

逗号运算符有序列点：左边先完成，再算右边。它常出现在 `for` 的初始化或迭代部分：

```c
for (i = 0, j = 10; i < j; ++i, --j) {
    ...
}
```

## 2.8 优先级与结合性

优先级决定“先结合谁”，结合性决定“同级的运算符从左还是从右结合”。它不决定求值顺序。

从高到低，常见运算符可以粗略排成：

| 优先级 | 运算符 | 结合性 |
|-------:|--------|--------|
| 1 | `()` `[]` `->` `.` 后缀 `++` `--` | 左 |
| 2 | 前缀 `++` `--`、`!` `~`、一元 `+` `-`、`*` `&`、`sizeof`、`(类型)` | 右 |
| 3 | `*` `/` `%` | 左 |
| 4 | `+` `-` | 左 |
| 5 | `<<` `>>` | 左 |
| 6 | `<` `<=` `>` `>=` | 左 |
| 7 | `==` `!=` | 左 |
| 8 | `&` | 左 |
| 9 | `^` | 左 |
| 10 | `\|` | 左 |
| 11 | `&&` | 左 |
| 12 | `\|\|` | 左 |
| 13 | `?:` | 右 |
| 14 | `=` `+=` `-=` `*=` `/=` `%=` `<<=` `>>=` `&=` `^=` `\|=` | 右 |
| 15 | `,` | 左 |

几个容易看错的例子：

```c
2 + 3 * 4        // 14，不是 20
(2 + 3) * 4      // 20
10 - 4 - 3       // 3，左结合，等价于 (10 - 4) - 3
10 - (4 - 3)     // 9
1 << 2 + 1       // 8，因为 + 比 << 高，等价于 1 << (2 + 1)
a = b = 3        // a = (b = 3)
x = y == 3       // x = (y == 3)
```

最后两个例子说明：**优先级高的运算符先结合，但赋值仍然可以出现在最外层。** 读复杂表达式时，不要靠记忆硬猜，加括号是最便宜的可读性投资。

`&` 和 `*` 还是“双重身份”的典型：

```c
int x = 10;
int *p = &x;     // & 是取地址
int y = *p;      // * 是解引用
int z = x & 3;   // & 是按位与
```

同一个符号在不同上下文里含义不同，靠的是语法位置。

## 2.9 求值顺序、序列点与未定义行为

这是本章最重要的部分。

### 优先级不等于求值顺序

```c
f() + g() * h()
```

优先级告诉我们它等价于 `f() + (g() * h())`，但不告诉我们 `f`、`g`、`h` 谁先被调用。函数参数的求值顺序同样未指定：

```c
printf("%d %d\n", f(), g());   // f 和 g 谁先执行？未指定
```

如果 `f` 和 `g` 互不影响，通常没关系；如果它们修改同一个对象，就可能变成未定义行为。

### 序列点

C 的求值被一系列**序列点**（sequence point）分隔。两个序列点之间，一个对象的修改最多发生一次，而且读取旧值不能和修改它混在一起。

常见的序列点包括：

- 完整表达式结束时（通常是 `;`）；
- `&&`、`||` 的第一个操作数求值之后；
- `?:` 的条件求值之后；
- 逗号运算符的左操作数求值之后；
- 函数调用时，所有实参求值之后、函数体执行之前。

C11 之后标准更常用“sequenced before”（先序于）来描述这些关系，但初学阶段用“序列点”理解已经够用。

### 未定义行为的经典例子

```c
i = i++;      // UB：同一个对象在两个序列点之间被修改两次
i++ + i++;    // UB：两个修改之间没有序列点
a[i] = i++;   // UB：读取 i 和修改 i 没有确定先后
printf("%d %d\n", i++, i++);   // UB：实参求值顺序未指定
```

这些表达式不是“结果不确定”，而是**程序已经失去了标准给出的任何保证**。编译器可以假设它们不会出现，从而做出任何优化。它们可能在你的机器上“看起来正常”，换一个编译器、优化级别或平台就崩溃。

安全的写法是拆成多条语句：

```c
int old = i;
i = i + 1;
```

或者使用有明确顺序的运算符：

```c
int x = (i++, i++, i);   // 逗号运算符保证从左到右
```

但即使合法，也不代表好读。清楚比聪明重要。

### `sizeof` 的求值规则

```c
int counter = 0;
size_t n = sizeof(counter++);   // counter 仍然是 0
```

`sizeof` 的操作数通常不会被求值，因为编译器只需要知道它的类型。例外是可变长度数组（VLA）：它的 `sizeof` 要到运行时才知道。

## 2.10 类型转换与整数提升

表达式里的类型转换有两种：

1. **隐式转换**：由编译器按规则自动插入。
2. **显式转换**：你用 `(类型)` 写出来。

### 整数提升

`char`、`short`、`_Bool`、位域在参与算术时，通常会先提升为 `int`：

```c
char a = 100;
char b = 100;

sizeof(a + b)   // 通常是 sizeof(int)
```

两个 `char` 相加，结果类型通常是 `int`。这也是为什么 `printf("%d", a + b)` 合适，而 `printf("%c", a + b)` 可能不符合预期。

### 通常算术转换

二元运算符两边类型不同时，会转换成共同类型。常见规则：

- 如果有一边是 `long double`，另一边转成 `long double`。
- 否则如果有 `double`，转成 `double`。
- 否则如果有 `float`，转成 `float`。
- 否则做整数提升，再按等级和无符号性转换。

这解释了一个经典陷阱：

```c
int minus_one = -1;
unsigned int one = 1;

minus_one < one   // 假，-1 被转换成 UINT_MAX
```

`-1` 不是“比 1 小”，而是在比较前被转换成了巨大的无符号数。

### 显式转换

```c
(double)7 / 2      // 3.5
(int)3.9           // 3，向零截断
(unsigned char)300 // 在 8 位 unsigned char 上得到 44
```

强制转换只产生一个值，不改变原对象。它也不能“修复”未定义行为：把一个越界指针转换成 `void *` 再转回来，仍然是越界指针。

3. `show_bitwise`：无符号位运算、移位、清除最低位 1；
4. `show_assignment`：复合赋值、前缀/后缀、逗号、条件运算符；

```sh
cc -std=c17 -Wall -Wextra -Wpedantic expressions.c -o expressions

```

输出里的 `~x` 会显示成 `0xFFFFFF4B`，这是因为 `unsigned int` 在你的平台上是 32 位。换一个平台，位数可能不同。

## 2.12 常见陷阱

| 陷阱 | 说明 |
|------|------|
| 以为 `2 && 4` 等于 2 | 逻辑运算符只返回 0 或 1。 |
| 把 `&` 当成 `&&` | `x & 1` 是取最低位，`x && 1` 是“x 非零”。 |
| 对负数做右移并假设算术右移 | 有符号负数的右移由实现定义。 |
| 左移有符号数导致溢出 | `1 << 31` 在 32 位 `int` 上是 UB；用 `1u << 31` 并确认宽度。 |
| `i = i++` | 两个序列点之间重复修改同一对象，UB。 |
| `printf("%d %d", i++, i++)` | 实参求值顺序未指定，且修改无序列点，UB。 |
| 依赖函数参数求值顺序 | C 不保证从左到右。 |
| 认为 `a < b < c` 是区间判断 | 它等价于 `(a < b) < c`，结果是 0 或 1。 |
| 用 `==` 比较浮点数 | 浮点是近似表示；比较差值或使用容差。 |
| 忘记 `?:` 和赋值是右结合 | `a = b = c` 和 `a ? b : c ? d : e` 都从右往左结合。 |

## 2.13 语法卡片

| 术语 | 一句话定义 | 本章例子 |
|------|------------|----------|
| 表达式 | 能求出一个值的构造 | `a + b` |
| 副作用 | 表达式对对象或环境的修改 | `i++`、`x = 1` |
| 短路求值 | `&&`/`\|\|` 在结果确定时跳过右操作数 | `p && *p` |
| 序列点 | 求值顺序上的分隔点 | `;`、`&&` 左侧之后 |
| 未定义行为 | 标准不给出任何保证的行为 | `i = i++` |
| 整数提升 | 小整数类型先转成 `int` 再运算 | `char + char` |
| 通常算术转换 | 二元运算统一两边类型 | `int + double` |
| 左值 | 能标识一个对象的表达式 | `x`、`*p`、`a[i]` |
| 右值 | 不能标识对象的纯值 | `x + 1`、`42` |
| 结合性 | 同级运算符从哪边开始结合 | `a - b - c` 左结合 |

## 2.14 练习

1. **算术**：用 `int` 和 `double` 分别计算 `7 / 2`、`-7 / 3`、`-7 % 3`，解释结果差异。
2. **逻辑与位运算**：对 `2` 和 `4` 分别计算 `&&`、`&`、`||`、`|`，写出每个结果的二进制。
3. **短路**：写一个函数 `int check(int x)`，打印自己被调用；用 `0 && check(1)`、`1 || check(2)`、`1 && check(3)` 观察调用次数。
4. **位运算**：用无符号整数实现“判断是否为 2 的幂”和“清除最低位 1”，并测试 0、1、2、3、8、0xB4。
5. **自增**：写 `int i = 0; int a = i++; int b = ++i;`，打印所有变量，画出每一步的值。
6. **求值顺序**：把 `i = i++`、`i++ + i++`、`a[i] = i++` 分别写进程序，打开 `-Wall -Wextra` 看编译器能否发现；不要运行它们。
7. **优先级**：不查表，先写出 `2 + 3 * 4`、`10 - 4 - 3`、`1 << 2 + 1`、`a = b = 3` 的结果，再编译验证。
8. **类型转换**：解释 `(double)7 / 2` 和 `(double)(7 / 2)` 的区别；再解释 `(unsigned char)300` 在 8 位字节平台上的结果。
9. **`sizeof`**：用 `sizeof(counter++)` 证明操作数没有被求值，再查 VLA 的例外。
