# 第 5 章 · 数组与指针

> **卷一 · 语言**　|　前置知识：第 4 章　|　建议用时：70 分钟

> 数组是连续的对象，指针是对象的地址。它们在表达式里经常相遇，但从来不是同一种东西。

这是 C 语言的分水岭。前面的章节里，每个对象都有名字，大小在编译期确定。从这一章开始，程序可以直接操作地址：用指针指向对象，用指针遍历数组，用指针把函数当作值传递。

指针也是 C 最容易出事故的地方。事故的根源通常不是“指针很难”，而是**数组、指针、边界和类型这四件事没有分开想清楚**。这一章会把它们拆开，再放回一起。

## 5.2 数组：连续的一块对象

数组是**同一类型元素的有序集合**，元素在内存里连续存放：

```c
int a[5];
```

这行声明了一个包含 5 个 `int` 的数组对象。元素是 `a[0]`、`a[1]`、`a[2]`、`a[3]`、`a[4]`，下标从 0 开始，到 `4` 结束。

数组的类型是 `int[5]`，元素类型是 `int`。`sizeof(a)` 等于 5 个 `int` 的总字节数，`sizeof(a[0])` 等于一个 `int` 的字节数。

### 初始化

```c
int a[5] = {10, 20, 30, 40, 50};
int partial[5] = {1, 2, 3};              // {1, 2, 3, 0, 0}
int designated[6] = {[1] = 20, [4] = 50}; // {0, 20, 0, 0, 50, 0}
const int primes[] = {2, 3, 5, 7, 11};   // 长度由初始化器推断为 5
```

规则：

- 初始化器可以少于元素个数，剩余元素自动补 0。
- 指定初始化（C99）用 `[下标] = 值` 指定元素，未指定的元素补 0。
- 方括号里不写长度、但有初始化器时，数组长度由最大的已初始化下标推断。
- 自动存储的数组如果不初始化，元素的值是不确定的；不要读取它们。

### 下标与边界

```c
a[0]    // 第一个元素
a[4]    // 最后一个元素
a[5]    // 越界，未定义行为
a[-1]   // 越界，未定义行为
```

C **不检查数组边界**。`a[5]` 在语法上是合法的，编译器不一定会阻止你；运行时可能读到别的对象、触发段错误，或者看起来“正常”。这正是它危险的地方。

下标类型可以是任何整数类型，但通常用 `size_t` 或 `int`。用 `size_t` 遍历可以避免有符号/无符号比较的警告：

```c
for (size_t i = 0; i < n; ++i) {
    printf("%d\n", a[i]);
}
```

### 数组不能整体赋值

```c
int a[5] = {1, 2, 3, 4, 5};
int b[5];

b = a;   // 错误：数组不能被赋值
```

数组不是“可以整体复制的值”。要复制，逐元素循环，或者用标准库的 `memcpy`：

```c
for (size_t i = 0; i < 5; ++i) {
    b[i] = a[i];
}
```

### 二维数组

```c
int m[2][3] = {
    {1, 2, 3},
    {4, 5, 6}
};
```

`m` 是“2 个元素的数组，每个元素是 3 个 `int` 的数组”。它在内存里按**行优先**连续存放：

```text
m[0][0] m[0][1] m[0][2] m[1][0] m[1][1] m[1][2]
```

所以：

- `sizeof(m) == 2 * 3 * sizeof(int)`
- `sizeof(m[0]) == 3 * sizeof(int)`
- `sizeof(m[0][0]) == sizeof(int)`

`m[i]` 的类型是 `int[3]`，不是 `int *`。但在大多数表达式里，它会退化成指向首元素的指针；这是下一节的主题。

## 5.3 数组名与退化

数组名在大多数表达式里会**退化**（decay）成指向首元素的指针：

```c
int a[5] = {10, 20, 30, 40, 50};
int *p = a;          // 等价于 int *p = &a[0];

a == &a[0]           // 真
*p == a[0]           // 真
```

但数组名不是指针。它们在三个地方明显不同：

1. **`sizeof`**：`sizeof a` 是整个数组的字节数；`sizeof p` 是指针的字节数。
2. **`&`**：`&a` 的类型是 `int (*)[5]`（指向整个数组的指针），不是 `int **`。
3. **赋值**：数组不能被赋值；指针可以。

C 标准规定的退化例外包括：作为 `sizeof` 的操作数、作为一元 `&` 的操作数，以及用字符串字面量初始化字符数组。除此之外，数组表达式通常都会变成指向首元素的指针。

### 函数参数里的数组

数组作为函数参数时，会退化成指针：

```c
void print_array(const int a[], size_t n);
/* 等价于 */
void print_array(const int *a, size_t n);
```

所以在函数内部：

```c
sizeof(a)   // 指针大小，不是数组大小
```

这就是为什么函数需要额外的长度参数。调用者知道数组有多大，函数不知道。

二维数组作为参数时，只有第一维可以省略：

```c
void print_matrix(const int m[2][3]);
/* 等价于 */
void print_matrix(const int (*m)[3]);
```

第二维及以后必须写出来，因为编译器需要知道“一行有多长”，才能计算 `m[i][j]` 的地址。

注意：C17 对多维数组参数的 `const` 限定比较严格。把 `int[2][3]` 实参传给 `const int (*)[3]` 形参，可能被诊断为指针类型不兼容。最省心的做法是让实参也声明为 `const`，或者参数不加 `const`。

### `int **` 不是二维数组

这是初学者最常见的误区之一：

```c
int m[2][3];     // 二维数组：一块连续的内存
int **p;         // 指向指针的指针：不是二维数组
```

`m` 退化成 `int (*)[3]`，不是 `int **`。`int **` 通常表示“指向一个指针数组”，每个指针可以指向不同的地方。它们的内存布局完全不同，不能互相赋值。

## 5.4 指针：对象的地址

指针是一个对象，它的值是一个地址。声明：

```c
int x = 42;
int *p = &x;
```

- `&x` 取得 `x` 的地址，类型是 `int *`。
- `p` 保存这个地址。
- `*p` 解引用，得到 `x` 这个对象；`*p` 是左值，可以赋值。

```c
*p = 43;        // 修改 x
printf("%d\n", x);   // 43
```

`&` 和 `*` 互为逆运算：

```c
&*p == p       // 真
*&x == x       // 真
```

### 声明语法

`*` 属于声明符，不属于类型名：

```c
int *p;    // p 是指向 int 的指针
int *p, q; // p 是指针，q 是 int
```

最后一行很容易误读。写成 `int* p, q;` 也不会改变语法：`q` 仍然是 `int`。为了避免这种歧义，建议一行只声明一个指针：

```c
int *p;
int q;
```

### 空指针

空指针不指向任何对象：

```c
int *p = NULL;

if (p != NULL) {
    printf("%d\n", *p);
}
```

`NULL` 定义在 `<stddef.h>` 等头文件里，可能是 `0`，也可能是 `(void *)0`。不要假设它的具体形式。C23 引入了 `nullptr`，但 C17 里用 `NULL` 或空指针常量 `0`。

解引用空指针是未定义行为。未初始化的指针更危险：它的值不确定，可能指向任何地方。声明指针时，如果暂时不知道它指向什么，就初始化为 `NULL`。

### 指针的类型

指针的类型决定了两件事：

1. 解引用时如何解释内存；
2. 指针算术一步走多少字节。

```c
int *ip;
char *cp;
double *dp;
```

在常见平台上，`ip + 1` 前进 `sizeof(int)` 字节，`cp + 1` 前进 1 字节，`dp + 1` 前进 `sizeof(double)` 字节。

不同类型的指针不能随意互相赋值：

```c
int *ip;
double *dp = ip;   // 约束违反，编译器会诊断
```

`void *` 是例外，下一节讲。

## 5.5 指针算术与数组

指针算术只在**同一个数组对象**（包括 one-past-the-end）内有定义：

```c
int a[5] = {10, 20, 30, 40, 50};
int *p = a;
int *q = a + 5;     // one-past-the-end，合法，但不能解引用

p + 0   // a[0]
p + 1   // a[1]
p + 4   // a[4]
p + 5   // one-past-the-end，合法
p + 6   // 越界，未定义行为
```

解引用只能发生在真实元素上：

```c
*(p + 4)   // 合法，a[4]
*(p + 5)   // 未定义行为：one-past-the-end 不能解引用
```

### 下标与指针的等价关系

```c
a[i] == *(a + i) == *(p + i) == p[i]
```

这四种写法在语义上等价。C 甚至允许 `i[a]`，因为 `a[i]` 被定义为 `*(a + i)`，加法可交换。但不要写 `i[a]`，它只会让读者困惑。

### 指针差值

两个指向同一数组的指针相减，得到它们之间的元素个数：

```c
int *begin = a;
int *end = a + 5;

end - begin   // 5，类型是 ptrdiff_t
```

`ptrdiff_t` 是有符号整数类型，打印用 `%td`。如果两个指针不属于同一个数组，相减是未定义行为。

### 指针遍历

```c
for (int *it = a; it != a + 5; ++it) {
    printf("%d\n", *it);
}
```

这是 C 里非常经典的遍历写法。注意：

- `a + 5` 是 one-past-the-end，合法；
- 循环条件是 `it != end`，不是 `it < end`（虽然同一数组内 `<` 也可以）；
- 不要在循环里解引用 `end`。

### 越界指针算术是未定义行为

```c
int *p = a + 6;   // UB：超出 one-past-the-end
p - a;            // 如果 p 已经越界，这个差值也没有保证
```

很多人以为“只要不解引用就没事”，但指针算术本身也有边界。标准只允许在数组对象内（含 one-past-the-end）形成指针。

### 指针比较

- `==` 和 `!=` 可以比较任意两个指针，包括空指针。
- `<`、`<=`、`>`、`>=` 只在同一数组/对象内有可移植意义；不同对象之间的相对顺序没有可移植保证。
- 不要用 `<` 比较两个 unrelated 指针来判断“谁在前”。

## 5.6 `const` 指针

`const` 和指针结合时，位置决定含义。从右往左读：

```c
const int *p;        // p 是指向 const int 的指针
int const *p;        // 同上
int *const p;        // p 是 const 指针，指向 int
const int *const p;  // p 是 const 指针，指向 const int
```

| 声明 | 能改 `p` 吗？ | 能改 `*p` 吗？ |
|------|:---:|:---:|
| `const int *p` | 能 | 不能 |
| `int *const p` | 不能 | 能 |
| `const int *const p` | 不能 | 不能 |

例子：

```c
int x = 1;
int y = 2;
const int ci = 10;

const int *pci = &ci;   // 不能通过 pci 修改 ci
pci = &x;                // 可以改指向

int *const cpi = &x;    // cpi 永远指向 x
*cpi = 3;                // 可以改 x
/* cpi = &y; */          // 错误：不能改 cpi

const int *const cpci = &ci;
/* *cpci = 11; */        // 错误
/* cpci = &x; */         // 错误
```

`const` 是接口契约。通过强制转换去掉 `const` 再修改一个真正定义为 `const` 的对象，是未定义行为。不要这么干。

## 5.7 指针的指针

指针本身也是对象，也有地址：

```c
int x = 42;
int *p = &x;
int **pp = &p;

*pp == p;     // 真
**pp == x;    // 真
```

`int **` 读作“指向 `int *` 的指针”。它常见于两种场景：

1. 函数需要修改调用者的指针（输出参数）；
2. 指向指针数组（例如 `char **argv`）。

不要把它和二维数组混为一谈。`int **` 指向的是“一个指针”，不是“一块连续的 int”。

## 5.8 指针数组与数组指针

这两个声明只差一对括号，含义完全不同：

```c
int *a[3];      // 数组，含 3 个 int * 元素
int (*p)[3];    // 指针，指向“含 3 个 int 的数组”
```

读法：

- `a` 先和 `[]` 结合，所以是数组；元素类型是 `int *`。
- `(*p)` 先和 `*` 结合，所以是指针；指向的类型是 `int[3]`。

例子：

```c
int x = 1, y = 2, z = 3;
int *ptrs[3] = {&x, &y, &z};   // 指针数组

int m[2][3] = {{1,2,3}, {4,5,6}};
int (*row)[3] = m;             // 指向第一行
row[1][2]                      // m[1][2]
```

`row + 1` 前进一整行（3 个 `int`），不是前进一个 `int`。

二维数组的函数参数：

```c
void print_matrix(const int m[2][3]);
/* 参数类型是 const int (*)[3] */
```

这里的第一维 `2` 可以省略，第二维 `3` 不能省略。

## 5.9 函数指针

函数也有地址。函数指针保存函数的入口地址：

```c
int square(int x)
{
    return x * x;
}

int (*fp)(int) = square;
int result = fp(5);      // 25
```

`(*fp)(5)` 也可以，`*` 在这里是可选的；函数名会转换成函数指针。

声明读法：

```c
int (*fp)(int);   // fp 是指针，指向“接受 int、返回 int”的函数
int *fp(int);     // fp 是函数，接受 int，返回 int *
```

括号不能省。函数指针可以作为参数，实现回调：

```c
int apply(int (*fn)(int), int x)
{
    return fn(x);
}

apply(square, 6);
```

函数指针不能做算术，也不能指向不同签名的函数（强制转换后调用是未定义行为）。C 没有闭包，也没有 lambda；需要携带上下文时，通常额外传一个 `void *` 参数。

## 5.10 `void *`

`void *` 是通用对象指针：

```c
int x = 42;
void *vp = &x;    // 任何对象指针都可以隐式转成 void *
int *ip = vp;     // 在 C 里可以隐式转回，不需要强制转换
```

规则：

- `void *` 可以和任何**对象指针**互相转换。
- `void *` 不能解引用，因为编译器不知道它指向什么类型；先转成具体类型。
- 标准 C 不允许对 `void *` 做算术；`vp + 1` 是 GNU 扩展。需要按字节移动时，转成 `unsigned char *`。
- 函数指针和 `void *` 之间的转换不保证可移植。

`const void *` 表示“指向 const 对象的通用指针”，常用于只读接口。

## 5.11 常见未定义行为与陷阱

| 行为 | 后果 |
|------|------|
| `a[n]` 越界访问 | 未定义行为；可能读到别的对象或崩溃。 |
| 解引用空指针 | 未定义行为，通常直接崩溃。 |
| 解引用未初始化指针 | 未定义行为；值不确定。 |
| 指针算术超出数组（或 one-past-end） | 未定义行为。 |
| 两个不同数组的指针相减 | 未定义行为。 |
| 返回局部变量的地址 | 函数返回后对象消失，指针悬空。 |
| 通过错误类型的指针访问对象 | 可能违反严格别名规则，未定义行为。 |
| 修改字符串字面量 | 未定义行为（第 6 章）。 |
| 用 `int **` 指向二维数组 | 类型和布局都不匹配，解引用后行为错误。 |
| 在函数里 `sizeof` 数组参数 | 得到指针大小，不是数组大小。 |

`const` 指针的错误不会变成运行时 bug，通常会在编译期被拦住；这正是一部分 `const` 的价值。

## 5.12 代码导览

本章有两个程序。

### [`arrays.c`](arrays.c)

1. 数组初始化、部分初始化、指定初始化；
2. `sizeof` 与元素个数；
3. 数组不能整体赋值，逐元素复制；

编译运行：

```sh
cc -std=c17 -Wall -Wextra -Wpedantic arrays.c -o arrays
./arrays
```

重点观察：

- `sizeof a` 是 20，`sizeof a[0]` 是 4；
- `print_array` 里的 `sizeof(a)` 是 8（指针大小）；
- `sizeof matrix` 是 24，`sizeof matrix[0]` 是 12；
- `safe_get(a, 5, 5)` 会拒绝越界下标。

### [`pointers.c`](pointers.c)

1. 取地址、解引用、修改对象；
2. 指针与数组：`a == &a[0]`、指针遍历、差值；
3. 空指针检查；
4. 通过指针交换；
5. 指针的指针；
6. `const` 指针的三种写法；
7. 指针数组与数组指针；
8. 函数指针和回调；
9. `void *`。

编译运行：

```sh
cc -std=c17 -Wall -Wextra -Wpedantic pointers.c -o pointers
./pointers
```

重点观察：

- `sizeof x` 是 4，`sizeof p` 是 8；
- `end - begin` 是 5，`mid - a` 是 2；
- `sizeof *row` 是 12，因为 `*row` 是一整行；
- `apply(square, 6)` 和 `apply(negate, 6)` 通过函数指针调用不同函数。

| 指针数组 | 元素为指针的数组 | `int *a[3];` |
| 数组指针 | 指向数组的指针 | `int (*p)[3];` |
| 函数指针 | 指向函数的指针 | `int (*fp)(int);` |
| `void *` | 通用对象指针 | `void *vp = &x;` |

## 5.14 练习

1. **反转数组**：原地反转一个 `int` 数组，用两个下标或两个指针实现。
2. **最大值**：写 `int max_index(const int a[], size_t n)`，返回最大元素的下标；空数组如何表示？
3. **计数**：写 `size_t count(const int a[], size_t n, int value)`，统计某个值出现次数。
4. **矩阵转置**：把 `int a[3][3]` 转置到 `int b[3][3]`，打印前后结果。
5. **指针遍历**：用 `*(a + i)`、`a[i]`、`p[i]` 三种写法打印同一个数组，确认输出一致。
6. **交换**：写 `void swap(int *a, int *b)`，在 `main` 里交换两个变量。
7. **`const` 练习**：分别声明 `const int *`、`int *const`、`const int *const`，尝试修改指针和 pointee，记录编译器错误。
8. **函数指针**：写四个函数 `add`、`sub`、`mul`、`div`，用函数指针数组做一个小型计算器分发器。
9. **二维数组参数**：写 `int sum_matrix(const int m[][3], size_t rows)`，计算矩阵元素和。
10. **类型辨析**：解释 `int **`、`int (*)[3]`、`int *[3]` 分别是什么，并各写一个声明。
11. **寻找元素**：写 `int *find(int *begin, int *end, int value)`，找到返回指向该元素的指针，找不到返回 `NULL`。
12. **悬空指针**：写一个返回局部变量地址的函数，编译并运行，观察结果；解释为什么它是未定义行为。
13. **one-past-end**：打印 `a + 5` 与 `a` 的差值，但不要解引用 `a + 5`。
14. **`sizeof` 陷阱**：把数组传给函数，在函数里打印 `sizeof`，解释为什么不是整个数组的大小。
