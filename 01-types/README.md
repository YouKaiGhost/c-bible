# 第 1 章 · 对象、类型与声明

> **卷一 · 语言**　|　前置知识：第 0 章　|　建议用时：35 分钟

> 类型不是贴在数据上的标签，而是编译器理解内存的语法。

第 0 章让程序说出了第一句话。这一章要问一个更底层的问题：那句话里的 `"Hello, World!\n"`，在内存里到底占多大地方？`int` 又是什么？为什么同样是整数，`int`、`long`、`unsigned int` 的行为不一样？

这一章只讲语言本身：对象、类型、声明、初始化、`sizeof` 和转换。标准库的 `printf` 仍然只是我们的扬声器。

## 1.1 本章语法地图

| 语法 | 本章出现的位置 |
|------|----------------|
| 对象与变量 | `int x = 10;` |
| 声明与定义 | `extern int x;`、`int x;` |
| 基本类型 | `char`、`short`、`int`、`long`、`long long`、`float`、`double`、`long double`、`_Bool` |
| `sizeof` 运算符 | `sizeof(int)`、`sizeof x` |
| 整数常量 | `42`、`052`、`0x2A`、`42u`、`42L`、`42ULL` |
| 浮点常量 | `1.0`、`1e3`、`0.5f`、`1.0L` |
| 类型转换 | `(unsigned int)-1`、`(double)7 / 2` |
| 初始化与赋值 | `int x = 10;`、`x = 20;` |
| `const` 限定符 | `const int answer = 42;` |
| 静态断言 | `_Static_assert(...)` |

## 1.2 对象：内存里的一块地方

C 标准把**对象**（object）定义成执行环境中的一块数据存储区域，它的内容可以表示值。这个名字听起来抽象，但它就是“内存里的一块地方”。

一个对象有三个关键属性：

1. **存储**：它在内存里占多少字节，地址在哪里。
2. **类型**：这些字节如何解释，能做哪些运算。
3. **生命期**：它从什么时候存在，到什么时候消失。

```c
int x = 42;
```

这行代码做的不只是“把 42 放进一个叫 x 的东西”。它声明了一个类型为 `int` 的对象 `x`，为它分配存储，并用值 `42` 初始化。类型决定了：

- `x` 占几个字节（由实现决定，常见是 4）；
- `x` 能表示哪些值（有符号还是无符号，范围多大）；
- 哪一些运算对 `x` 有意义（加减、取地址、和指针互转等）。

**变量**通常指一个有名字的对象。但对象不一定有名字：后面会看到动态分配的对象、复合字面量产生的对象。名字是语法层面的东西，对象是运行时的存储。

## 1.3 声明与定义：名字和存储不是一回事

这是 C 语言里最容易混淆的一对概念。

- **声明**（declaration）告诉编译器：某个名字存在，它是什么类型。
- **定义**（definition）除了声明名字，还真正分配存储，或者给出函数体。

看几个例子：

```c
extern int x;      // 声明：x 在别处定义
int x;             // 在文件作用域，这是暂定定义（tentative definition）
int x = 42;        // 定义：分配存储并初始化

int f(void);       // 函数声明（原型）
int f(void) {      // 函数定义：给出函数体
    return 1;
}
```

在块作用域里：

```c
void demo(void) {
    int y;         // 定义：自动存储，未初始化
    extern int z;  // 声明：z 在别处定义
}
```

一个名字可以声明很多次，但真正的定义通常只能有一次。文件作用域的 `int x;` 是“暂定定义”，链接阶段会与真正的定义合并；第 8 章会专门讲这套规则。

`typedef` 也是声明，但它声明的不是对象，而是类型别名：

```c
typedef unsigned long ulong;   // 给类型起别名，不分配存储
```

现在只需要记住一个判断方法：**这句话有没有让编译器为某个对象留出存储，或者为某个函数提供函数体？** 有，就是定义；没有，通常只是声明。

## 1.4 基本类型：C 只保证下限

C 的类型系统是围绕“实现”设计的。标准规定每种类型**至少**能表示什么，但不规定它一定是多少位。你写的代码如果假设 `int` 永远是 32 位，就已经把可移植性押上去了。

### 整数类型

| 类型 | 标准保证的最小范围 | 常见宽度 |
|------|--------------------|----------|
| `signed char` | 至少 -127 .. 127 | 8 位 |
| `unsigned char` | 至少 0 .. 255 | 8 位 |
| `char` | 同 `signed char` 或 `unsigned char`，由实现决定 | 8 位 |
| `short` | 至少 -32767 .. 32767 | 16 位 |
| `unsigned short` | 至少 0 .. 65535 | 16 位 |
| `int` | 至少 -32767 .. 32767 | 32 位 |
| `unsigned int` | 至少 0 .. 65535 | 32 位 |
| `long` | 至少 -2147483647 .. 2147483647 | 32 或 64 位 |
| `unsigned long` | 至少 0 .. 4294967295 | 32 或 64 位 |
| `long long` | 至少 -9223372036854775807 .. 9223372036854775807 | 64 位 |
| `unsigned long long` | 至少 0 .. 18446744073709551615 | 64 位 |

几个关键点：

- `char`、`signed char`、`unsigned char` 是**三种不同的类型**。普通 `char` 到底有符号还是无符号，由实现决定。
- `sizeof(char) == 1` 永远成立。这里的“1”是**一个 C 字节**，不是“8 位”。一个字节有多少位由 `CHAR_BIT` 给出，标准只保证它至少为 8。
- `short`、`int`、`long`、`long long` 的宽度满足：
  `sizeof(short) <= sizeof(int) <= sizeof(long) <= sizeof(long long)`。
- 标准只保证最小范围，所以 `int` 在 16 位机器上可以是 16 位。需要精确宽度时，用 `<stdint.h>` 里的 `int32_t`、`uint64_t` 等；但这些类型只有在实现确实支持该宽度时才存在。

### 布尔类型

C99 引入了 `_Bool`。它只有两个值：0 和 1。任何标量转成 `_Bool` 时，等于 0 得 0，不等于 0 得 1。

```c
_Bool flag = 0;
flag = 42;        // flag 变成 1，不是 42
```

C99 的 `<stdbool.h>` 提供了 `bool`、`true`、`false` 三个宏，让代码更好看。C23 起它们成为关键字，不再需要这个头文件。本书以 C17 为基线，所以代码里用 `_Bool`，并在需要时提一下 `<stdbool.h>`。

### 浮点类型

| 类型 | 常见宽度 | 说明 |
|------|----------|------|
| `float` | 32 位 | 单精度，至少 6 位十进制有效数字 |
| `double` | 64 位 | 双精度，至少 10 位十进制有效数字 |
| `long double` | 80/128 位 | 扩展精度，具体由实现决定 |

浮点数不是“带小数点的精确数”。`0.1` 在二进制浮点里通常不能精确表示，所以不要用 `==` 比较两个浮点结果。需要比较时，通常看差值是否小于一个容差；这是数值计算的话题，本章只建立“浮点是近似”的直觉。

浮点类型还可能是实现定义的格式（例如是否支持 IEEE 754、是否有无穷大和 NaN）。`<float.h>` 里的 `FLT_DIG`、`DBL_DIG`、`FLT_EPSILON` 等宏可以告诉你当前实现的精度。

### `void`、`size_t` 和 `ptrdiff_t`

- `void` 是**不完整类型**，不能定义对象。它只用于函数返回类型（表示不返回值）和参数列表（表示没有参数），以及 `void *` 这种通用对象指针。
- `size_t` 是 `sizeof` 的结果类型，也是表示对象大小的无符号整数类型。它定义在 `<stddef.h>` 等头文件里，具体宽度由实现决定。
- `ptrdiff_t` 是两个指针相减的结果类型，是有符号整数类型，也定义在 `<stddef.h>`。

`size_t` 是无符号的，这一点会在比较和减法里制造陷阱。打印它用 `%zu`，打印 `ptrdiff_t` 用 `%td`。

## 1.5 `sizeof`：编译器如何量对象

`sizeof` 是运算符，不是函数。它返回一个对象或类型占用的字节数，结果的类型是 `size_t`。

```c
printf("%zu\n", sizeof(int));   // 类型：必须加括号
printf("%zu\n", sizeof x);      // 对象：可以不加括号
```

几个必须建立的直觉：

1. `sizeof(char) == 1` 永远成立。
2. `sizeof` 的结果单位是 C 字节，不是 bit。要知道一个字节几位，看 `CHAR_BIT`。
3. `sizeof` 在大多数情况下是编译期常量。C99 的可变长度数组（VLA）是例外，它的 `sizeof` 要到运行时才能算。
4. `sizeof` 的操作数**通常不会被求值**：

```c
int counter = 0;
size_t n = sizeof(counter++);
// counter 仍然是 0，因为 sizeof 不需要真的执行 counter++
```

5. `sizeof` 数组得到整个数组的字节数，`sizeof` 指针得到指针本身的字节数。数组和指针在这一点上完全不同，第 5 章会展开。

`sizeof` 返回 `size_t`，所以它和负整数比较时会出问题：

```c
if (sizeof(int) > -1) {
    // 这个条件为假！
}
```

`-1` 会被转换成很大的无符号数，于是 `4 > 一个巨大的数` 为假。编译器通常会用 `-Wsign-compare` 提醒你，但最好的办法是不要写这种比较。

## 1.6 字面量：源码里的值

字面量是直接写在源代码里的值。它的类型不是“看起来像什么”，而是由语法和值共同决定的。

### 整数常量

```c
42        // 十进制
052       // 八进制，前导 0
0x2A      // 十六进制，前导 0x
42u       // unsigned int
42L       // long
42ULL     // unsigned long long
```

C17 **没有**二进制字面量，也没有数字分隔符。`0b1010` 和 `1'000'000` 是 C23 才加入的语法；GCC 可能把它们当扩展接受，但加上 `-Wpedantic` 就会提醒你这不是标准 C17。

无后缀整数常量的类型，按“能容纳该值的第一个类型”选取：

- 十进制：`int` → `long` → `long long`
- 八进制/十六进制：`int` → `unsigned int` → `long` → `unsigned long` → `long long` → `unsigned long long`

后缀会改变候选列表。比如 `42u` 从 `unsigned int` 开始找，`42L` 从 `long` 开始找。这就是为什么打印时格式必须匹配：

```c
printf("%d\n", 42);      // 正确
printf("%ld\n", 42L);    // 正确
printf("%d\n", 42L);     // 错误：格式与类型不匹配，行为未定义
```

`printf` 的格式串不是类型安全的接口。编译器能在很多情况下用 `-Wformat` 检查出来，但它不是语言层面的保证。

### 字符常量

```c
'A'       // 类型是 int，值是字符集里 A 的编码
'\n'      // 换行符
'\x41'    // 十六进制转义，同样是 A
```

在 C 里，字符常量 `'A'` 的类型是 `int`，不是 `char`。所以 `sizeof('A') == sizeof(int)`，在常见平台上等于 4。这一点和 C++ 不同：C++ 的字符常量类型是 `char`。

多字符常量（如 `'AB'`）的值由实现定义，不应该用于可移植代码。

### 浮点常量

```c
1.0       // double
1e3       // double
0.5f      // float
1.0L      // long double
```

没有后缀的浮点常量是 `double`。`f`/`F` 表示 `float`，`l`/`L` 表示 `long double`。

## 1.7 有符号、无符号与转换

这是 C 里最容易产生“看起来对、其实是未定义行为”的地方。

### 无符号算术是模运算

无符号整数的运算按 2^N 取模，结果永远在类型范围内：

```c
unsigned int u = 0;
u - 1;   // 结果是 UINT_MAX，而不是 -1
```

这是**定义良好**的行为，不是溢出错误。哈希、位运算、字节处理经常依赖它。

### 有符号溢出是未定义行为

```c
int x = INT_MAX;
x + 1;   // 未定义行为，不是“变成 INT_MIN”
```

C 标准没有规定有符号溢出后发生什么。编译器可以假设它永远不会发生，于是做出在你看来“匪夷所思”的优化。永远不要依赖有符号回绕。

### 有符号与无符号的转换

有符号转无符号时，如果值不能表示，结果按 2^N 取模：

```c
int negative = -1;
unsigned int u = (unsigned int)negative;   // UINT_MAX
```

无符号转有符号时，如果值超出目标范围，结果是实现定义的（C17）。不要依赖它。

### 通常算术转换与 `-1 < 1u`

当二元运算符两边类型不同时，C 会做**通常算术转换**。一个常见规则是：如果无符号类型的等级不低于有符号类型，就有符号操作数会被转换成无符号类型。

```c
int minus_one = -1;
unsigned int one = 1;

minus_one < one;   // 假！-1 被转换成 UINT_MAX
```

这就是为什么“无符号更安全”的说法并不绝对。无符号适合表示大小、位模式和模运算，不适合表示可能为负的差值。

### 整数提升

`char`、`short`、`_Bool` 和位域在参与算术时，通常会先提升为 `int`（如果 `int` 能表示它们的所有值），否则提升为 `unsigned int`。

```c
char a = 100;
char b = 100;

sizeof(a + b);   // 通常是 sizeof(int)，不是 sizeof(char)
```

两个 `char` 相加，结果类型通常是 `int`。这解释了为什么 `printf("%d", a + b)` 是合适的。

### 除法与取余

从 C99 开始，整数除法向零截断，余数的符号与被除数相同：

```c
-7 / 3    // -2
-7 % 3    // -1
```

除数为 0 是未定义行为；`INT_MIN / -1` 也可能溢出，同样是未定义行为。

### 浮点转整数

```c
double d = 3.9;
int i = (int)d;   // 3，向零截断
```

如果截断后的值无法用目标整数类型表示，行为未定义；NaN 和无穷大也属于这种情况。转换前要自己检查范围。

## 1.8 初始化与赋值

```c
int x = 10;   // 初始化：在定义时给初值
x = 20;       // 赋值：修改已经存在的对象
```

这两行看起来相似，语义不同。初始化发生在对象创建时；赋值发生在对象已经存在之后。

`const` 对象一旦定义，就不能再通过赋值修改：

```c
const int answer = 42;
answer = 43;   // 编译错误
```

但 `const` 不等于“编译期常量”。在 C 里：

```c
const int n = 5;
int a[n];      // 这是 VLA（可变长度数组），不是常量数组
```

数组 bounds 需要整数常量表达式，而 `const int` 变量不是整数常量表达式。`switch` 的 `case` 标号也一样，不能写 `case n:`。

初始化还有一些细节：

- 自动存储的对象不初始化时，值是不确定的；读取它是未定义行为（或至少是未指定值，取决于类型和场景）。
- 静态存储的对象不初始化时，会被零初始化。
- 数组初始化可以只给前几个元素，其余元素自动补 0：

```c
int a[5] = {1, 2, 3};   // {1, 2, 3, 0, 0}
```

- C99 支持指定初始化：

```c
int a[5] = {[2] = 9, [4] = 7};   // {0, 0, 9, 0, 7}
```

### `_Static_assert`

`_Static_assert` 是 C11 的编译期断言。它在编译时检查一个整数常量表达式，失败就报错：

```c
_Static_assert(sizeof(int) >= 2, "int must hold at least 16 bits");
_Static_assert(sizeof(char) == 1, "sizeof(char) is always 1");
```

它适合检查平台假设，而不是运行时条件。C23 增加了 `static_assert` 拼写，并允许不加消息；旧的 `_Static_assert` 仍然保留。

## 1.9 代码导览

[`types.c`](types.c) 分成五段：

1. `show_sizes`：打印各类型的 `sizeof` 和 `CHAR_BIT`；
2. `show_ranges`：打印 `<limits.h>`、`<float.h>` 和 `<stdint.h>` 里的范围；
3. `show_literals`：观察十进制、八进制、十六进制、后缀和字符常量；
4. `show_conversions`：观察无符号回绕、有符号/无符号转换、除法和取余；
5. `show_declarations`：观察初始化、赋值、`const`、数组 `sizeof` 和 `sizeof` 的不求值特性。

编译运行：

```sh
cc -std=c17 -Wall -Wextra -Wpedantic types.c -o types
./types
```

在你的机器上，`sizeof(int)`、`sizeof(long)`、`CHAR_MIN` 可能和示例输出不同。这不是教材错了，而是 C 标准故意留给实现的自由度。**把输出当作“这台机器的事实”，不要当作“C 语言的常数”。**

## 1.10 常见陷阱

| 陷阱 | 说明 |
|------|------|
| 假设 `int` 是 32 位 | 标准只保证至少 16 位；需要精确宽度用 `int32_t` 并检查可用性。 |
| 假设 `char` 有符号 | `char` 的符号性由实现决定；处理字节用 `unsigned char`。 |
| 假设一个字节是 8 位 | `CHAR_BIT` 可能大于 8；`sizeof` 的单位是 C 字节。 |
| 用 `%d` 打印 `long` 或 `size_t` | 格式不匹配是未定义行为；用 `%ld`、`%zu`、`%td`、`%jd`。 |
| 依赖有符号溢出 | 有符号溢出是未定义行为；无符号回绕才是定义良好的。 |
| 直接比较有符号和无符号 | 有符号值可能被转换成巨大的无符号值；打开 `-Wsign-compare`。 |
| 把 `sizeof` 和负数比较 | `sizeof` 返回 `size_t`，负数会被转换成无符号数。 |
| 认为 `const` 是编译期常量 | C 的 `const` 不是 C++ 的 `constexpr`；`const int n` 不能当数组常量大小。 |
| 用 `==` 比较浮点数 | 浮点是近似表示；比较差值或使用容差。 |
| 以为 `long` 一定是 64 位 | Windows LLP64 上 `long` 是 32 位，Linux LP64 上通常是 64 位。 |

## 1.11 语法卡片

| 术语 | 一句话定义 | 本章例子 |
|------|------------|----------|
| 对象 | 一块可以表示值的数据存储区域 | `int x = 42;` |
| 声明 | 引入名字和类型，不一定分配存储 | `extern int x;` |
| 定义 | 分配存储或提供函数体 | `int x = 42;` |
| 初始化 | 对象创建时给初值 | `int x = 10;` |
| 赋值 | 修改已存在对象的值 | `x = 20;` |
| `sizeof` | 求对象或类型占用的字节数，结果是 `size_t` | `sizeof(int)` |
| 整数提升 | 小整数类型参与运算前提升为 `int` | `char + char` |
| 通常算术转换 | 二元运算前把两边转换成共同类型 | `int + unsigned int` |
| 限定符 | 给类型附加约束，如只读 | `const int answer` |
| 静态断言 | 编译期检查整数常量表达式 | `_Static_assert(...)` |

## 1.12 练习

1. **量一量**：打印你平台上 `char`、`short`、`int`、`long`、`long long`、`float`、`double`、`long double`、`void *` 的 `sizeof`，再打印 `CHAR_BIT`。哪些结果与“常见平台”不同？
2. **范围**：用 `<limits.h>` 打印 `INT_MIN`、`INT_MAX`、`UINT_MAX`、`LONG_MIN`、`LONG_MAX`。用 `INT_MAX + 1u` 和 `(unsigned)INT_MAX + 1` 做对比，解释哪个是定义良好的。
3. **字符符号**：打印 `CHAR_MIN` 和 `CHAR_MAX`，判断你的平台把普通 `char` 当作有符号还是无符号。再用 `signed char` 和 `unsigned char` 各自验证。
4. **安全加法**：写一个函数，在不触发有符号溢出的前提下判断两个 `int` 相加是否会溢出。提示：先处理正负号，再用 `INT_MAX - b`。
5. **回绕**：用 `unsigned int u = 0; u - 1;` 观察结果，并解释为什么这不是“错误”。
6. **`sizeof` 不求值**：写 `int n = 0; size_t s = sizeof(n++);`，打印 `s` 和 `n`。再查一查 VLA 的 `sizeof` 为什么是例外。
7. **格式匹配**：故意用 `%d` 打印 `long`、用 `%zu` 打印 `int`，打开 `-Wall -Wextra -Wformat`，看编译器能否发现。不要运行格式不匹配的程序。
8. **C 与 C++**：解释为什么 C 里 `sizeof('A') == sizeof(int)`，而 C++ 里通常是 1。
9. **`const` 不是常量**：写 `const int n = 5; int a[n];`，用 `-Wvla` 编译，观察它被当作 VLA。再试 `case n:`，看编译器如何拒绝。
