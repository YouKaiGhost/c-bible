# 第 6 章 · 字符串与字符

> **卷一 · 语言**　|　前置知识：第 5 章　|　建议用时：45 分钟

> C 没有字符串类型。它只有字符数组，以及一个约定：用 `'\0'` 标记结束。

字符串是 C 里最容易被低估的主题。看起来只是“一段文字”，实际上它同时涉及字符编码、数组、指针、内存边界和未定义行为。

这一章只讲语言层面的东西：`char`、字符常量、字符串字面量、字符数组、空字符，以及用指针遍历字符串。标准库的 `strlen`、`strcpy` 只是参照物；我们会自己实现一遍，看看它们到底在做什么。

| 字符串字面量 | `"Hello"`、`"Hello, " "World!"` |

| 空字符 | `'\0'` |

| UTF-8 | 一个中文字符通常占 3 个字节 |

## 6.2 `char`：最小的整数类型

`char` 是 C 里最小的整数类型，`sizeof(char) == 1`。它通常用来存放字符的编码，但本质上仍然是整数。

```c
char c = 'A';
printf("%c\n", c);   // A
printf("%d\n", c);   // 65（常见 ASCII 平台）
```

几个关键点：

- `'A'` 是**字符常量**，在 C 里类型是 `int`，不是 `char`。所以 `sizeof('A') == sizeof(int)`。
- `char` 可能是 signed 或 unsigned，由实现决定。处理字节值时，用 `unsigned char` 更安全。
- `signed char`、`unsigned char`、`char` 是三种不同的类型。
- `char` 保证至少 8 位；`CHAR_BIT` 给出具体位数。

字符常量里的值取决于**执行字符集**。常见平台使用 ASCII 的超集，所以 `'A'` 是 65；标准并不保证这一点。

### 转义序列

有些字符不能直接写在源码里，或者写出来不可见。C 用反斜杠引入转义序列：

| 写法 | 含义 |
|------|------|
| `'\n'` | 换行 |
| `'\t'` | 水平制表符 |
| `'\r'` | 回车 |
| `'\\'` | 反斜杠 |
| `'\''` | 单引号 |
| `'\"'` | 双引号 |
| `'\0'` | 空字符（值为 0） |
| `'\x41'` | 十六进制转义，`A` |
| `'\101'` | 八进制转义，`A` |

两个容易混淆的地方：

```c
'\0'   // 空字符，值为 0
'0'    // 字符零，常见平台上值为 48
```

`'\0'` 是字符串的结束标记，`'0'` 只是普通字符。

十六进制转义会尽可能吃进后面的十六进制数字：

```c
"\x41B"   // 不是 'A' 后面跟 'B'，而是十六进制 0x41B
```

如果后面还要跟十六进制字符，拆成两个字符串或加分隔：

```c
"\x41" "B"   // "AB"
```

### 字符与整数

`char` 可以参与算术：

```c
char c = 'A';
c = c + 1;    // 'B'（常见 ASCII 平台）
```

但不要假设字母在编码里一定连续。C 标准只保证数字字符 `'0'` 到 `'9'` 连续；字母的连续性由执行字符集决定。可移植的代码应使用字符分类函数或显式映射。

## 6.3 字符串字面量

字符串字面量是用双引号包围的字符序列：

```c
"Hello"
```

它不是“一个字符串对象”，而是**一个字符数组**，末尾自动带一个空字符 `'\0'`。所以：

```c
sizeof("Hello") == 6
```

5 个可见字符加 1 个空字符。`strlen("Hello")` 则是 5，因为它不数末尾的空字符。

### 字符串字面量的存储与修改

字符串字面量有静态存储期，程序运行期间一直存在。但它**不保证可修改**：

```c
char *p = "Hello";
p[0] = 'J';   // 未定义行为
```

很多编译器会把字符串字面量放在只读段，运行时直接崩溃；也可能看起来“成功”，但仍然是未定义行为。

正确的做法：

```c
const char *p = "Hello";   // 只读指针，明确表示不修改
```

如果你需要修改，复制到字符数组：

```c
char s[] = "Hello";        // 数组，内容可修改
s[0] = 'J';                // 合法
```

### 相邻字面量拼接

相邻的字符串字面量会在翻译阶段拼接：

```c
"Hello, " "World!"   // "Hello, World!"
```

这不是 `+` 运算符，而是编译期的字面量拼接。它常用于把长字符串拆成多行。

### 字面量可能被合并

标准不保证两个内容相同的字符串字面量是不同的对象。下面比较的是地址，不是内容：

```c
"hello" == "hello"   // 结果未指定，不要依赖
```

要比较内容，用 `strcmp` 或自己逐字符比较。

## 6.4 字符数组与字符指针

这两种写法看起来很接近，含义不同：

```c
char a[] = "Hello";        // 数组：复制 6 个字符，可修改
const char *p = "Hello";   // 指针：指向字面量，不应修改
```

| 写法 | 类型 | `sizeof` | 可修改内容？ |
|------|------|----------|:---:|
| `char a[] = "Hello";` | `char[6]` | 6 | 可以 |
| `const char *p = "Hello";` | `const char *` | 指针大小 | 不可以 |
| `char *p = "Hello";` | `char *` | 指针大小 | 不应修改（UB） |

### 没有空字符的字符数组

如果数组大小刚好等于字符数，字符串字面量的结尾空字符就放不进去：

```c
char s[5] = "Hello";
```

`sizeof(s) == 5`，内容是 `H e l l o`，**没有 `'\0'`**。它可以当作字符数组使用，但不是 C 字符串；传给 `strlen`、`printf("%s")` 等函数会越界读取，属于未定义行为。

安全的写法：

```c
char s[6] = "Hello";   // 留出空字符
char s[] = "Hello";    // 让编译器推断为 6
```

### 字符串长度

```c
size_t len = 0;
while (s[len] != '\0') {
    ++len;
}
```

这个循环假设 `s` 确实以 `'\0'` 结尾。如果数组没有空字符，循环会一直读到内存里的某个 0，可能越界。**字符串函数不检查缓冲区边界，它们只找 `'\0'`。**

### 字符串不是值

C 没有字符串赋值和字符串比较运算符：

```c
char a[] = "hello";
char b[6];

b = a;            // 错误：数组不能赋值
if (a == b) ...   // 比较的是地址，不是内容
```

复制用循环或 `strcpy`，比较用 `strcmp` 或自己实现。

## 6.5 自己实现三个字符串函数

标准库 `<string.h>` 提供了 `strlen`、`strcpy`、`strcmp` 等函数。它们的实现不神秘，核心就是指针遍历。

### `string_length`

```c
size_t string_length(const char *s)
{
    size_t n = 0;
    while (s[n] != '\0') {
        ++n;
    }
    return n;
}
```

`const char *` 表示函数不会修改字符串内容。返回值用 `size_t`，因为长度不可能是负数。

### `copy_string`

标准库的 `strcpy` 不接收目标容量，调用者必须自己保证目标足够大。下面这个版本接收容量，并保证截断后仍然以 `'\0'` 结尾：

```c
void copy_string(char *dst, size_t cap, const char *src)
{
    size_t i = 0;

    if (cap == 0) {
        return;
    }

    while (i + 1 < cap && src[i] != '\0') {
        dst[i] = src[i];
        ++i;
    }
    dst[i] = '\0';
}
```

`i + 1 < cap` 留出最后一个位置放空字符。`cap == 0` 时什么也不做，因为连一个字节都放不下。

### `compare_strings`

`strcmp` 的返回值只需要看符号：负数表示左边小，0 表示相等，正数表示左边大。不要假设它一定返回 -1 或 1。

```c
int compare_strings(const char *a, const char *b)
{
    const unsigned char *pa = (const unsigned char *)a;
    const unsigned char *pb = (const unsigned char *)b;

    while (*pa != '\0' && *pa == *pb) {
        ++pa;
        ++pb;
    }
    return (int)*pa - (int)*pb;
}
```

为什么要转成 `unsigned char`？因为 `char` 可能是有符号的。直接比较负的 `char` 会让高位字节排到前面，破坏字典序。标准库的 `strcmp` 也是按 `unsigned char` 比较的。

## 6.6 缓冲区、截断与越界

C 字符串最常见的 bug 是**缓冲区溢出**：

```c
char buf[8];
strcpy(buf, "this is too long");   // 越界写，未定义行为
```

`strcpy` 不知道 `buf` 有多大，它只会一直复制到源字符串的 `'\0'`。如果源比目标长，就会写穿目标。

几个标准库函数的陷阱：

- `strcpy`：不检查目标容量。
- `strncpy`：最多复制 n 个字符，但**不保证**结果以 `'\0'` 结尾。
- `strcat`：不检查目标剩余容量。
- `sprintf`：不检查目标容量；`snprintf` 接收容量，但仍要检查返回值是否被截断。
- `strlen`：只找 `'\0'`，不检查边界。

安全的策略：

1. 目标缓冲区总是多留一个字节给 `'\0'`。
2. 复制前知道目标容量。
3. 截断后显式补 `'\0'`。
4. 必要时检查函数的返回值，判断是否发生截断。

## 6.7 字符串数组

有两种常见结构：

```c
const char *names[] = {"Alice", "Bob", "Carol"};
```

这是一个**指针数组**：每个元素是一个 `const char *`，指向各自的字符串字面量。`sizeof(names) / sizeof(names[0])` 得到元素个数。

另一种是二维字符数组：

```c
char names[][8] = {"Alice", "Bob", "Carol"};
```

这是一块连续的二维数组，每一行最多 8 个字符（含 `'\0'`）。它的内存布局和指针数组完全不同：

- 指针数组：指针连续，字符串可以分散在任意位置，每行长度可以不同。
- 二维数组：所有字符连续存放，每行宽度固定，可能浪费空间。

`argv` 是 `char **`，属于第一种：一个指向指针数组的指针。

## 6.8 UTF-8、宽字符与编码

`char` 是一个字节。一个字节不等于一个字符，更不等于一个 Unicode 码点。

在 UTF-8 中，一个中文字符通常占 3 个字节：

```c
"你好"   // 6 个字节，加 1 个空字符
```

所以：

```c
sizeof("你好") == 7
strlen("你好") == 6
```

`strlen` 数的是字节，不是汉字。终端能把 `E4 BD A0 E5 A5 BD` 显示成“你好”，是终端按 UTF-8 解码的结果。

C 还提供了其他字符串形式：

- `L"..."`：宽字符串，元素类型是 `wchar_t`，宽度由实现决定。
- `u8"..."`：C11 的 UTF-8 字符串；在 C17 中元素类型是 `char`。
- `u"..."`：元素类型是 `char16_t`。
- `U"..."`：元素类型是 `char32_t`。

宽字符和 Unicode 的处理涉及 locale、编码转换和库函数，不属于“只讲语法”的核心。这里只需要记住：**`char` 字符串是字节序列，不是字符序列。** 需要按“字符”处理时，必须知道编码，并使用相应的库。

## 6.9 代码导览

[`strings.c`](strings.c) 分成几段：

1. `char`、字符常量、转义序列、`sizeof('A')`；
2. 字符串字面量的 `sizeof`、字符数组、字符指针；
3. 修改字符数组 vs 不修改字面量；
4. `copy_string` 的复制与截断；
5. `compare_strings` 的字典序比较；
6. 字符串指针数组；
7. UTF-8 字符串的字节数和字节内容。

编译运行：

```sh
cc -std=c17 -Wall -Wextra -Wpedantic strings.c -o strings
./strings
```

重点观察：

- `sizeof("Hello") == 6`，`string_length("Hello") == 5`；
- `sizeof(greeting) == 6`，但 `sizeof(literal) == 8`（指针大小）；
- `char exact[5] = "Hello";` 的 `sizeof` 是 5，没有空字符；
- `"你好"` 的 `sizeof` 是 7，`string_length` 是 6；
- `print_bytes` 打印出 UTF-8 的 6 个字节。

## 6.10 常见陷阱

| 陷阱 | 说明 |
|------|------|
| `char s[5] = "Hello";` 当作字符串 | 没有 `'\0'`；传给字符串函数会越界。 |
| 修改字符串字面量 | 未定义行为；需要修改时复制到数组。 |
| 用 `==` 比较字符串 | 比较的是地址，不是内容；用 `strcmp`。 |
| `strcpy` 复制到小缓冲区 | 越界写；使用带容量的复制。 |
| `strncpy` 一定补 `'\0'` | 不保证；手动补。 |
| `strlen` 返回 `int` | 返回 `size_t`；打印用 `%zu`。 |
| `%s` 打印没有 `'\0'` 的数组 | 越界读；未定义行为。 |
| `sizeof` 字符串指针 | 得到指针大小，不是字符串长度。 |
| 把 `'0'` 当成 `'\0'` | 前者是字符零，后者是空字符。 |
| 认为 `strlen` 数的是字符 | 它数的是字节；UTF-8 下一个汉字可能占 3 字节。 |
| 比较有符号 `char` 的字节 | 转成 `unsigned char` 再比较；`strcmp` 也是这么做的。 |
| 返回局部字符数组的指针 | 函数返回后数组消失，指针悬空。 |

## 6.12 练习

1. **实现 `strlen`**：写 `size_t my_strlen(const char *s)`，再和 `<string.h>` 的 `strlen` 比较。
2. **实现 `strcpy`**：写一个带容量参数的复制函数，保证结果以 `'\0'` 结尾；测试刚好放下、截断、空字符串三种情况。
3. **实现 `strcmp`**：按 `unsigned char` 比较，返回负数、0、正数；不要假设返回 -1/1。
4. **反转字符串**：原地反转一个 `char[]`，用两个指针从两端向中间走。
5. **回文判断**：判断一个字符串是否回文；先只处理 ASCII 大小写，再考虑空格和标点。
6. **查找字符**：写 `char *find_char(char *s, char c)`，找到返回指针，找不到返回 `NULL`。
7. **统计**：统计字符串里的字母、数字、空格和其他字符；只用 ASCII 范围判断。
8. **字符串数组**：用 `const char *names[]` 保存 5 个名字，打印每个名字和它的长度。
9. **UTF-8**：打印 `"你好"` 的 `sizeof`、`strlen` 和每个字节的十六进制；解释为什么 `strlen` 不是 2。
10. **缓冲区**：把 `"Hello"` 复制到 `char buf[5]`，观察 `strcpy` 的越界；再用带容量的函数修复。不要在有重要数据的程序里运行越界版本。
11. **字面量**：分别声明 `char a[] = "hello";` 和 `const char *p = "hello";`，比较 `sizeof`、可修改性和生命周期。
12. **空字符**：写 `char s[5] = "Hello";`，只打印 `sizeof`，不要传给 `strlen`；解释原因。
