# 第 10 章 · 未定义行为与可移植性

> **卷一 · 语言**　|　前置知识：第 9 章　|　建议用时：60 分钟

> 标准没有说“你可以这样做”，也没有说“你不可以这样做”。它说的是：如果你这样做，标准就不再保证任何事情。

前面九章里，我们反复遇到几个词：未定义行为、实现定义、未指定。它们不是教材的免责声明，而是 C 语言对象模型的一部分。

这一章把这些词讲清楚，并给出一份常见的“地雷清单”。目标不是让你背下所有 UB，而是让你在看到可疑代码时，知道该问什么问题。

## 10.1 本章语法地图

| 概念 | 本章出现的位置 |
|------|----------------|
| 未定义行为（UB） | 有符号溢出、越界、空指针解引用 |
| 未指定行为 | 函数参数求值顺序、padding 内容 |
| 实现定义行为 | `char` 符号性、整数宽度、字节序 |
| 约束违反 | 类型不兼容、`case` 非整数常量 |
| 不确定值 | 未初始化的自动对象 |
| 严格别名 | 通过不兼容类型的指针访问对象 |
| 可移植类型 | `size_t`、`ptrdiff_t`、`intmax_t` |
| 检查工具 | 警告、sanitizer、静态分析 |

## 10.2 四种“没有唯一答案”

C 标准对不同情况有不同的要求。先把四个概念分开：

### 未定义行为（undefined behavior，UB）

标准对程序的行为**没有任何要求**。程序可以崩溃、输出垃圾、看起来正常运行，或者让编译器生成完全意想不到的代码。

```c
int x = INT_MAX;
x = x + 1;          // UB：有符号溢出
```

UB 不一定在运行时才发生。编译器可以在编译期假设“UB 永远不会发生”，并据此优化代码。所以 UB 有时会“影响过去”：让前面看起来无关的代码被删掉或改变。

### 未指定行为（unspecified behavior）

标准给出了一组可能的行为，但没有规定选哪一个，也不要求实现文档化。每次执行、每个编译器都可能不同。

```c
printf("%d %d\n", f(), g());   // f 和 g 谁先执行？未指定
```

如果 `f` 和 `g` 互不影响，通常没关系；如果它们共享状态，就可能变成 UB。

### 实现定义行为（implementation-defined behavior）

实现必须选择一种行为，并且**文档化**。不同平台可以不同，但在同一个实现上通常是稳定的。

```c
char c = 0xFF;
printf("%d\n", c);   // c 的值取决于 char 是否有符号
```

`char` 的符号性、`int` 的宽度、字节序、结构体填充、位域布局，都是实现定义的。

### 约束违反（constraint violation）

程序违反了标准中的“约束”条款，编译器**必须给出诊断**。它可能拒绝编译，也可能在诊断后继续生成程序。

```c
int *p;
double *q = p;   // 约束违反：不兼容的指针类型
```

约束违反不一定是 UB，但程序已经不是严格符合标准的程序。不要依赖“编译器只是警告了一下”。

### 不确定值（indeterminate value）

未初始化的自动对象具有不确定值：

```c
int x;
printf("%d\n", x);   // 读取不确定值
```

读取不确定值可能得到任意结果，某些类型/场景下是 UB，某些情况下是未指定值。无论哪种，都不要读。静态存储的对象会被零初始化，自动对象不会。

## 10.3 UB 是一份契约

C 标准不是“运行时检查器”。它更像一份契约：

> 如果你的程序不触发 UB，实现保证按标准描述的方式工作；如果你触发 UB，实现什么都不保证。

编译器在优化时会利用这个契约。例如：

```c
int f(int x)
{
    if (x + 1 < x) {
        return 1;
    }
    return 0;
}
```

在数学上，`x + 1 < x` 似乎对某些 `x` 可能成立；但在 C 里，`x + 1` 一旦溢出就是 UB。编译器可以假设它永远不溢出，于是这个条件永远为假，整个 `if` 被删掉。

这不是编译器“坏了”，而是程序先违约了。

### “在我机器上能跑”不是证据

UB 的一个恶劣之处是它经常**看起来正常**：

- 在 `-O0` 下正常，`-O2` 下崩溃；
- 在这台机器上正常，换一台机器出错；
- 加一行 `printf` 后正常，删掉后又出错；
- 测试环境正常，生产环境数据触发边界。

这不是玄学，而是 UB 让编译器有了不同的假设空间。

## 10.4 常见 UB 清单

下面这些写法都不要出现在真实代码里。代码片段只用于识别，不要直接运行。

### 1. 有符号整数溢出

```c
int x = INT_MAX;
x + 1;              // UB
INT_MIN / -1;       // UB（常见平台上）
```

无符号溢出是定义良好的模运算；有符号溢出不是。

### 2. 除零与取余零

```c
int x = 1 / 0;      // UB
int y = 1 % 0;      // UB
```

浮点除零通常得到无穷大或 NaN（如果实现支持），但整数除零是 UB。

### 3. 数组和指针越界

```c
int a[5];
a[5] = 1;           // UB
a[-1] = 1;          // UB

int *p = a + 6;     // UB：超出 one-past-the-end
```

形成 one-past-the-end 指针（`a + 5`）是合法的，但解引用它不行。

### 4. 空指针、未初始化指针、悬空指针

```c
int *p = NULL;
*p = 1;             // UB

int *q;
*q = 1;             // UB：q 的值不确定

int *r = local_address();
*r = 1;             // UB：对象已经消失
```

解引用前检查空指针；指针初始化；不要返回局部变量的地址。

### 5. 两个序列点之间重复修改

```c
i = i++;            // UB
i++ + i++;          // UB
a[i] = i++;         // UB
```

规则是：两个序列点之间，一个对象最多被修改一次，而且读取旧值不能和修改它混在一起。

### 6. 移位越界

```c
int x = 1;
x << 32;            // UB：在 32 位 int 上，移位数 >= 类型宽度
x << -1;            // UB：负数移位
1 << 31;            // UB：有符号左移溢出（32 位 int）
```

对无符号类型，左移在移位数合法时是模运算；对有符号类型，负值或溢出是 UB。负的有符号右移是实现定义的。

### 7. 修改字符串字面量

```c
char *p = "hello";
p[0] = 'H';         // UB
```

需要修改时，复制到 `char` 数组。

### 8. 严格别名违规

```c
float f = 1.0f;
int *p = (int *)&f;
*p = 0;             // UB：通过不兼容类型的指针访问对象
```

通过 `char *`、`unsigned char *` 访问对象字节是允许的；通过不兼容类型读写通常是 UB。类型双关用 `memcpy`，不要用指针强转。

### 9. `printf` 格式不匹配

```c
long x = 1;
printf("%d\n", x);  // UB：格式与参数类型不匹配
```

`printf` 不是类型安全的。用 `%ld`、`%zu`、`%td`、`%jd`、`%ju` 等匹配类型。

### 10. `memcpy` 处理重叠区域

```c
char buf[16] = "abcdefghij";
memcpy(buf + 2, buf, 5);   // UB：源和目标重叠
```

重叠时用 `memmove`。

### 11. 修改真正 const 的对象

```c
const int x = 1;
int *p = (int *)&x;
*p = 2;             // UB：对象本身是 const
```

如果对象本身不是 const，只是通过 const 指针看它，去掉 const 后修改是允许的；但通常说明接口设计有问题。

### 12. 数据竞争

```c
/* 两个线程同时写同一个非原子对象，且没有同步 */
shared_counter++;   // UB：数据竞争
```

C11 的内存模型把数据竞争定义为 UB。`volatile` 不能解决这个问题；用 `_Atomic`、互斥量或其他同步机制。

### 13. 释放后使用、重复释放

```c
int *p = malloc(sizeof *p);
free(p);
*p = 1;             // UB：use-after-free
free(p);            // UB：double free
```

这些是标准库层面的 UB，但同样致命。

### 14. 空无限循环

```c
while (1) {
    /* 没有 I/O、volatile 访问、原子操作或同步 */
}
```

C11 允许实现假设某些没有副作用的循环会终止，从而优化掉它们。需要真正等待时，使用 `volatile`、原子操作或平台提供的等待原语。

## 10.5 实现定义与未指定的例子

### 实现定义

| 行为 | 说明 |
|------|------|
| `char` 是否有符号 | 由实现决定；用 `CHAR_MIN` 判断。 |
| `int`/`long` 的宽度 | 标准只给最小值；用 `sizeof`、`<limits.h>`。 |
| 有符号整数的表示 | C17 允许补码、反码、符号-数值。 |
| 负的有符号右移 | 可能是算术右移，也可能是逻辑右移。 |
| `enum` 的底层类型 | 由实现选择；`sizeof` 不保证。 |
| 位域布局 | 顺序、宽度、跨单元方式由实现定义。 |
| 字节序 | 大端、小端或混合。 |
| 结构体 padding | 成员之间和末尾的填充由实现决定。 |
| 无符号转有符号越界 | 结果由实现定义。 |
| `%p` 的输出格式 | 由实现定义。 |

### 未指定

| 行为 | 说明 |
|------|------|
| 函数参数的求值顺序 | `f() + g()` 谁先？未指定。 |
| 大多数二元运算符的操作数顺序 | 优先级只决定结合，不决定求值顺序。 |
| padding 字节的内容 | 结构体赋值后，padding 的值不确定。 |
| 相同字符串字面量是否合并 | 地址可能相同，也可能不同。 |
| 不同翻译单元的静态初始化顺序 | 未指定；不要跨文件依赖初始化顺序。 |
| 不同对象的指针相对顺序 | `<` 比较没有可移植意义。 |

### 约束违反

| 行为 | 说明 |
|------|------|
| 不兼容指针赋值 | 编译器必须诊断。 |
| `case` 不是整数常量表达式 | 约束违反。 |
| `break` 不在循环/switch 内 | 约束违反。 |
| 函数参数个数不匹配 | 约束违反（有原型时）。 |
| 对 `const` 对象赋值 | 约束违反。 |

## 10.6 可移植性清单

### 不要假设固定宽度

```c
int x;          // 至少 16 位，不一定是 32 位
long y;         // 至少 32 位，Windows 上常见 32 位，Linux 上常见 64 位
```

需要精确宽度时：

```c
#include <stdint.h>

int32_t x;      // 只有在实现支持精确 32 位类型时才存在
uint64_t y;
```

如果 `int32_t` 不存在，代码就不可移植到该平台。需要“至少 N 位”时，用 `int_least32_t`；需要“最快”时，用 `int_fast32_t`。

### 用对类型和格式

| 用途 | 类型 | 格式 |
|------|------|------|
| 对象大小 | `size_t` | `%zu` |
| 指针差值 | `ptrdiff_t` | `%td` |
| 最大有符号整数 | `intmax_t` | `%jd` |
| 最大无符号整数 | `uintmax_t` | `%ju` |
| 固定宽度 | `int32_t` 等 | `<inttypes.h>` 的 `PRId32` 等 |

### 不要假设字节序

```c
unsigned int value = 0x1234u;
unsigned char bytes[sizeof value];
memcpy(bytes, &value, sizeof value);
```

在小端机器上可能看到 `34 12 00 00`，在大端机器上可能看到 `00 00 12 34`。需要固定字节序时，逐字节写入：

```c
buf[0] = (unsigned char)(value >> 24);
buf[1] = (unsigned char)(value >> 16);
buf[2] = (unsigned char)(value >> 8);
buf[3] = (unsigned char)value;
```

这要求 `value` 至少 32 位；先检查或用固定宽度类型。

### 不要直接序列化结构体

padding、对齐、字节序、位域布局都不可移植。逐字段序列化，或者使用明确的协议。

### 不要依赖有符号回绕

无符号回绕是定义良好的；有符号溢出是 UB。需要模运算时，用无符号类型；需要检测溢出时，做边界检查。

### 不要用 `volatile` 做同步

`volatile` 只保证访问不被优化掉；它不保证原子性，也不提供内存顺序。多线程用 `_Atomic` 或互斥量。

### 不要忽略严格别名

通过不兼容类型的指针访问对象是 UB（有少数例外）。需要重新解释字节时，用 `memcpy` 或 `unsigned char`。

## 10.7 工具：让 UB 现形

### 编译器警告

```sh
cc -std=c17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow \
   -Wcast-qual -Wstrict-prototypes -Wformat=2 -Wundef \
   portable.c -o portable
```

这些警告不是万能的，但能提前发现大量问题。把警告当错误：

```sh
cc ... -Werror ...
```

### Sanitizer

GCC 和 Clang 支持运行时检查器：

```sh
cc -std=c17 -Wall -Wextra -Wpedantic -g -O1 \
   -fsanitize=address,undefined -fno-sanitize-recover=all \
   portable.c -o portable-san
./portable-san
```

- **AddressSanitizer (ASan)**：越界、use-after-free、double-free、泄漏等。
- **UndefinedBehaviorSanitizer (UBSan)**：有符号溢出、移位、空指针、对齐等。

它们不能抓住所有 UB。通过 sanitizer 不代表程序没有 UB，但失败通常意味着确实有问题。

### 其他工具

- 静态分析器（Clang Static Analyzer、GCC `-fanalyzer`）；
- Valgrind；
- 模糊测试（fuzzing）；
- 在不同编译器、优化级别、平台上跑测试。

### `assert` 与 `_Static_assert`

```c
#include <assert.h>

assert(p != NULL);                          // 运行时检查
_Static_assert(sizeof(int) >= 2, "int");   // 编译期检查
```

`assert` 在定义 `NDEBUG` 时会被禁用，适合检查“绝不应该发生”的内部不变量，不适合处理用户输入。

## 10.8 代码导览

[`portable.c`](portable.c) 只演示安全写法：

1. `show_sizes`：打印 `CHAR_BIT`、各类型大小、范围、对齐；
2. `show_arithmetic`：无符号回绕，以及用边界检查避免有符号溢出；
3. `TYPE_NAME`：用 `_Generic` 在编译期选择类型名；
4. `show_bytes`：用 `memcpy` 查看对象的字节表示；
5. `show_overlap`：用 `memmove` 安全处理重叠区间。

编译运行：

```sh
cc -std=c17 -Wall -Wextra -Wpedantic portable.c -o portable
./portable
```

再跑一次 sanitizer：

```sh
cc -std=c17 -Wall -Wextra -Wpedantic -g -O1 \
   -fsanitize=address,undefined -fno-sanitize-recover=all \
   portable.c -o portable-san
./portable-san
```

重点观察：

- `INT_MAX + 1` 被 `safe_add` 拒绝，而不是实际执行溢出；
- `0u - 1` 得到 `UINT_MAX`，这是定义良好的；
- `0x1234` 的字节顺序在这台机器上是 `34 12 00 00`，换平台可能不同；
- `memmove` 把重叠区域正确复制成 `ababcdehij`；
- `_Generic` 区分 `int`、`long`、`double`，`float` 落到 `default`。

## 10.9 常见误区

| 误区 | 事实 |
|------|------|
| “UB 只是结果随机” | UB 没有任何保证；编译器可以删除代码或改变前面逻辑。 |
| “能编译就是合法程序” | 约束违反和 UB 都可能编译通过。 |
| “我机器上跑通了” | 换编译器、优化级别、平台就可能失败。 |
| “无符号一定安全” | 无符号不会溢出 UB，但会有回绕和逻辑错误。 |
| “`volatile` 可以替代原子操作” | 它不保证原子性和内存顺序。 |
| “`memcpy` 可以处理重叠” | 重叠是 UB；用 `memmove`。 |
| “`int` 就是 32 位” | 标准只保证至少 16 位。 |
| “`char` 就是 8 位” | `CHAR_BIT` 可能大于 8；`sizeof(char)` 永远是 1 个 C 字节。 |
| “`long` 就是 64 位” | Windows LLP64 上常见 32 位。 |
| “`printf` 格式错了只是输出难看” | 格式不匹配是 UB。 |
| “`free` 后指针还能用” | use-after-free 是 UB。 |
| “跨文件静态初始化顺序是固定的” | 未指定；不要依赖。 |

## 10.10 概念卡片

| 术语 | 一句话定义 | 例子 |
|------|------------|------|
| 未定义行为 | 标准不给出任何保证 | 有符号溢出、越界 |
| 未指定行为 | 一组可能行为，不要求文档化 | 实参求值顺序 |
| 实现定义行为 | 实现必须选择并文档化 | `char` 符号性、字节序 |
| 约束违反 | 违反标准约束，必须诊断 | 不兼容指针赋值 |
| 不确定值 | 未初始化自动对象的值 | `int x;` |
| 严格别名 | 通过不兼容类型访问对象 | `float *` 转 `int *` |
| 可移植类型 | 不假设固定宽度的类型 | `size_t`、`intmax_t` |
| 数据竞争 | 未同步的并发冲突访问 | 两个线程写同一变量 |

## 10.11 练习

1. **分类**：把下面每一项归类为 UB、未指定、实现定义或约束违反：
   - `int` 溢出；
   - `printf("%d", 1L)`；
   - `char` 是否有符号；
   - 函数参数求值顺序；
   - 两个不同数组的指针相减；
   - `case` 标签不是常量；
   - 读取未初始化局部变量；
   - `struct` 的 padding 内容。
2. **安全加法**：扩展 `safe_add`，写 `safe_sub`、`safe_mul`，覆盖 `INT_MAX`、`INT_MIN`、0、正负数。
3. **Sanitizer**：把本章 README 里的一个有符号溢出片段放进临时程序，用 `-fsanitize=undefined` 编译运行，观察诊断；再改成安全版本。
4. **格式串**：故意用 `%d` 打印 `long`、用 `%s` 打印 `int *`，打开 `-Wformat=2`，记录诊断；不要运行。
5. **字节序**：用 `memcpy` 打印一个整数的字节；再写一个函数，把 32 位值按大端顺序写入 `unsigned char[4]`。
6. **重叠复制**：分别用 `memcpy` 和 `memmove` 处理重叠区间；解释为什么前者是 UB，后者安全。
7. **严格别名**：用 `float` 和 `int *` 写一个类型双关程序，在 `-O2` 下运行；再用 `memcpy` 写安全版本。不要依赖前者的结果。
8. **可移植性表**：在你的平台上打印 `CHAR_BIT`、各整数类型大小、`CHAR_MIN`、`INT_MAX`、`LONG_MAX`、`SIZE_MAX`，并标注哪些是标准保证的，哪些是实现定义的。
9. **`_Generic`**：扩展 `TYPE_NAME`，支持 `char`、`unsigned int`、`float`、`long long`，观察 `_Generic` 如何匹配类型。
10. **数据竞争**：如果环境支持线程，写两个线程同时增加一个普通 `int`，用 ThreadSanitizer（`-fsanitize=thread`）观察竞争；再改成 `_Atomic int` 或互斥量。
11. **空循环**：写一个没有副作用的 `while (1) {}`，用 `-O2` 编译，观察编译器是否删除它；解释 C11 的相关规则。
12. **审计**：挑一个你写过的 C 程序，用 `-Wconversion -Wshadow -Wcast-qual -Wformat=2` 编译，记录并修复警告。
